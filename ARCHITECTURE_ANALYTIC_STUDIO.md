# 🏛 ANALYTIC STUDIO — архитектура

*Черновик 2026-08-10. Пишется после дня, в котором три анализа оказались недействительны,
а нашёл это не тест, а один график, на который посмотрел человек.*

---

## I. Принцип, из которого следует всё остальное

Архитектура строится не вокруг «что мы хотим считать», а вокруг того, чтобы каждый
известный режим отказа стал **структурно невозможен**:

| режим отказа | цена 2026-08-09/10 | как закрывается |
|---|---|---|
| контракт данных | 39.6% дублей → зеркало 73%/26% из арифметики | единственная дверь к данным, `assert_contract` до первой цифры |
| lookahead | `_near(±w)` в живом движке, 2 построенных setup-а | все временные величины через `as_of()`; `shift(-k)` = ошибка сборки |
| множественность | 312,189 ячеек без объявленного `k` | бюджет до запуска, ledger считает всё |
| непереносимость | ранги выходов mined↔OOS ρ = −0.04 | OOS-окно резервируется **до** поиска; остальное — в forward-реестр |

> **Ни один статистический тест не ловит первые два.** Кластерные интервалы, `n_eff`,
> matched control, полоса случайности, mined/OOS — все прошли на данных, описывавших
> не тот мир. Значит эти предохранители лежат **ниже** статистики, в слое сборки данных.

## II. Что входит — реестр источников

Каждый источник регистрируется с контрактом. Нет контракта — нет источника.

| источник | что даёт | ключ публичности | статус |
|---|---|---|---|
| `bars` ×5 TF | OHLCV + 415 колонок | `date` | ✅ есть, дедуп обязателен |
| `earnings_dates` | 120,721 дат отчётов, 3,532 тикера | **SEC `filingDate`** | ✅ есть |
| `insider_tx` | 65,004 Form 4, 3,318 тикеров | **`filed_date`** (не `tx_date`: лаг 65 дн) | ✅ есть, глубина ~2.5 мес |
| `ticker_meta` | сектор, SIC, employees, market_cap | `updated_at` — **снимок** | ⚠️ `market_cap` запрещён исторически |
| **`facts` (SEC XBRL)** | разводнение, кэш, долг, burn | **`filed`** | ❌ фаза 2 |
| GEX / опционы | OI, greeks, IV | 15-мин задержка, **без истории** | ⚠️ forward-only |
| intraday 15m/1h/4h | подтверждение | `datetime` | ✅ есть |

**Правило источника.** Обязан объявить: (а) ключ наблюдения, (б) момент, когда информация
стала публичной, (в) присутствуют ли делистнутые имена, (г) allowlist примитивов,
(д) явный список запрещённых колонок с причиной.

## IV. Pipeline — ворота, которые **отказывают**

*Ревизия 2026-08-10 после внешнего разбора. Четыре правки приняты, две добавлены из наших
собственных инцидентов. Обоснование каждой — в шапке `studio_gates.py`.*

```
SOURCE
  ↓  PIT ACCESS FIREWALL          feature: as_of(), будущее = FATAL
                                  label:   forward(), будущее РАЗРЕШЕНО, namespace y_*
                                  построитель масок физически не видит y_*
FRAME                             дедуп · prev_ok · страты · as-of join
  ↓  PRE-REGISTER                 spec · family_id · search_space_hash · declared_k · окна
MEASURE                           matched control · clustered CI · n_eff · плато · бакеты
  ↓  INTEGRITY GATES  ← FATAL, поодиночке, без голосования → INVALID
       data_contract · lookahead · survivorship · oos_contamination
       undeclared_search · execution_timing
  ↓  HUMAN CHECK                  verify_sample обязателен: N попаданий отрисованы для глаза
DESTROY  ← SOFT, взвешивается совокупно
       dependence · regime · stability · concentration · mechanism
ACCOUNT
       ledger · DSR(family) · BH-FDR · chance band на блочной перестановке
VERDICT   BUILD · BOOSTER · WATCH · NULL · VETO · **INVALID**
  ↓  FEASIBILITY                  частота · ёмкость · спред vs эффект · конкуренция за слоты
FREEZE → FORWARD → PROMOTE / VETO
```

### Почему INTEGRITY отделён от DESTROY

Старое правило было «≥2 линзы нашли дефект → kill». Это **категориальная ошибка**, и
проверяется она нашим же багом: дубликаты строк нашла бы **только** линза контракта данных.
Остальные четыре честно сказали бы «всё в порядке» — арифметика была безупречной.
Голосованием 1/5 находка **прошла бы**.

> `lookahead` — не аргумент против сигнала. Это значит, что **эксперимента не было.**

Отсюда шестой вердикт. `NULL` = «проверили корректно, эджа нет». `INVALID` = «результат
нельзя интерпретировать». Для истории исследований это разные записи.

### Уровень доказательности — поле каждого вердикта

| уровень | что значит |
|---|---|
| `backtest` | искали на этом окне — самое слабое, что можно сказать |
| `historical-oos` | скрипт не читал, **но исследователь этот период уже знал** — эпистемически загрязнён |
| `frozen-forward` | спецификация запечатана до появления баров — `k = 1` |
| `live` | торгуется |

**Вердикт уровня `backtest` — кандидат на заморозку, никогда не продвижение.**

### Blind mode = анонимизация, а не сессия без памяти

Агент, видящий `NVDA / январь 2023`, знает, что было дальше. Настоящий blind — это
`SEC_1842 / T0`, без календаря и абсолютных цен. **Но утечка сильнее, чем кажется:** ряд,
сделавший 10× в 2023-м, узнаётся и без тикера. Поэтому blind применяется узко — **к выбору
порогов и окон**, где и живёт вся наша утечка, а не к измерению.

## V. COMBO LAB — здесь живёт множественность

Комбинаторика — самая опасная часть. 2026-08-09 она выдала 46 комбинаций, 48 правил выхода
и 312,189 ячеек, и всё это оказалось шумом. Три вещи встроены в API, а не добавлены после:

```python
fam = register_family("seq_TT_T6",                       # ① семья ДО поиска
        space=dict(head=TOKENS, mid=TOKENS, tail=["T6"]),#    declared_k из пространства
        mined_window="2021-05→2023-12",                  # ② OOS зарезервирован ДО
        oos_window="2024-01→2026-07",
        selection_metric="median_ret_pct")
lab = ComboLab(fam); lab.run()          # ранжирует ТОЛЬКО на mined
lab.chance_band()                       # ③ блочная перестановка — печатается всегда
lab.freeze_top(3)                       # финалисты → forward-реестр, НЕ в книгу
```

**Семья регистрируется до поиска.** `family_of()` схлопывает 119 setup-ов в 65 механически —
но само правило схлопывания было придумано во время аудита, глядя на результаты.
Множественность утекает ровно там.

### Chance band — блочная перестановка, не i.i.d.

Старая версия брала случайные ячейки **i.i.d. из пула доходностей**. Это уничтожает
кластеризацию по датам, а у нас `deff = 6.3`. Слабый оппонент → узкая полоса → находки
объявляются значимыми, когда они не значимы.

Правильно: **перемешивать метки ячеек внутри каждой даты**. Рыночный день, поднявший всё,
остаётся целиком; исчезает только связь «ячейка → доходность».

Проверено на вчерашних же данных (25,257 сделок, 46 ячеек, 1,251 дата):

| | p95 разброса |
|---|---|
| старый null (i.i.d.) | **2.116** ← им и пользовались |
| новый null (перестановка внутри дат) | **2.432** |

**Старая полоса была уже в 1.15 раза.** Вчерашние выводы уцелели (наблюдалось 1.965 —
внутри обеих), но **по удаче**: выйди что-нибудь в плюс, я объявил бы «вне случайности»
против заниженного порога. И более чистая формулировка того же: лучшая ячейка дала
`+1.275`, а чистая случайность кладёт лучшую ячейку на `+1.501` (p95) — **то есть ниже
случайной.**

## VI. Агенты, скилы, человек

| роль | кто | почему |
|---|---|---|
| контракт, измерение, вердикт | **код** | должен **отказывать**, а не соглашаться |
| процедура исследования | **скил** `quant-study` | план-first, порядок гейтов, формат вердикта |
| **DESTROY — 5 линз** | **агенты, параллельно** | единственное место, где мульти-агентность совпадает с нашими режимами отказа |
| слепой дизайн спецификации | **агент без памяти** | слой A загрязнения снимается только отдельной сессией |
| широкие сканы | **агенты** | когда ответ — список, а не утверждение |
| генерация гипотез | **человек** | агент множит `k` и не считает его |
| «обязан ли механизм быть верным» | **человек** | этот вопрос к одному графику нашёл то, что пропустили 5 слоёв |

**Различие:** агент допускается туда, где его задача — **разрушать**, и не допускается туда,
где он **порождает**.

## VIII. Поверхности

```
CLI    python studio.py study <spec.yaml> · combo · forward · ledger · sources
API    /api/studio/{study,combo,forward,ledger,sources}      (read-only отчёты)
UI     вкладка 🔬 Analytic Studio:
         ├ Sources    — что подключено, контракт, свежесть
         ├ Study      — спецификация → вердикт с решающим гейтом
         ├ Combo Lab  — пространство, полоса случайности, mined→OOS
         ├ Forward    — реестр + «дней до читаемости»
         └ Ledger     — k по семьям, DSR, FDR
```

UI **не считает** — показывает результат CLI/API. Одна вычислительная тропа: два пути
с разными контрактами — это в точности причина бага 2026-08-09.
