# 🏛 ANALYTIC STUDIO — архитектура

*Черновик 2026-08-10. Пишется после дня, в котором три анализа оказались недействительны,
а нашёл это не тест, а один график, на который посмотрел человек.*

---

## I. Принцип, из которого следует всё остальное

Архитектура строится не вокруг «что мы хотим считать», а вокруг того, чтобы каждый
известный режим отказа стал **структурно невозможен**:

| режим отказа | цена 2026-08-09/10 | как закрывается |
|---|---|---|
| контракт данных | 39.6% дублей → зеркало 73%/26% из арифметики | единственная дверь к данным, `assert_contract` до первой цифры |
| lookahead | `_near(±w)` в живом движке, 2 построенных setup-а | все временные величины через `as_of()`; `shift(-k)` = ошибка сборки |
| множественность | 312,189 ячеек без объявленного `k` | бюджет до запуска, ledger считает всё |
| непереносимость | ранги выходов mined↔OOS ρ = −0.04 | OOS-окно резервируется **до** поиска; остальное — в forward-реестр |

> **Ни один статистический тест не ловит первые два.** Кластерные интервалы, `n_eff`,
> matched control, полоса случайности, mined/OOS — все прошли на данных, описывавших
> не тот мир. Значит эти предохранители лежат **ниже** статистики, в слое сборки данных.

## II. Что входит — реестр источников

Каждый источник регистрируется с контрактом. Нет контракта — нет источника.

| источник | что даёт | ключ публичности | статус |
|---|---|---|---|
| `bars` ×5 TF | OHLCV + 415 колонок | `date` | ✅ есть, дедуп обязателен |
| `earnings_dates` | 120,721 дат отчётов, 3,532 тикера | **SEC `filingDate`** | ✅ есть |
| `insider_tx` | 65,004 Form 4, 3,318 тикеров | **`filed_date`** (не `tx_date`: лаг 65 дн) | ✅ есть, глубина ~2.5 мес |
| `ticker_meta` | сектор, SIC, employees, market_cap | `updated_at` — **снимок** | ⚠️ `market_cap` запрещён исторически |
| **`facts` (SEC XBRL)** | разводнение, кэш, долг, burn | **`filed`** | ❌ фаза 2 |
| GEX / опционы | OI, greeks, IV | 15-мин задержка, **без истории** | ⚠️ forward-only |
| intraday 15m/1h/4h | подтверждение | `datetime` | ✅ есть |

**Правило источника.** Обязан объявить: (а) ключ наблюдения, (б) момент, когда информация
стала публичной, (в) присутствуют ли делистнутые имена, (г) allowlist примитивов,
(д) явный список запрещённых колонок с причиной.

## IV. Pipeline — 7 стадий, между ними ворота, которые **отказывают**

**`0 · SOURCE`** — адаптер объявляет контракт.
*Ворота:* нет ключа публичности → источник не регистрируется.

**`1 · FRAME`** — сборка; дедуп, `prev_ok`, страты, as-of join разреженных источников.
*Ворота:* `assert_contract` — дубли `(ticker,date)`, обратные даты, `universe='index'`,
календарная смежность, невероятная доля баров >45%.

**`2 · SPEC`** — вопрос + бюджет + окно, **до первого числа**.
*Ворота:* > 50 ячеек без `mined_window`/`oos_window` → отказ.

**`3 · MEASURE`** — matched control (включая переменную отбора), day-clustered CI, `n_eff`,
плато, $-бакеты, концентрация.
*Ворота:* ячейка без базиса → отказ; порог на неописанной колонке → отказ; превышение
бюджета → отказ.

**`4 · DESTROY`** — пять линз, параллельно, каждой задание **опровергнуть**:

```
L1 контракт        дубли · смежность · корп. действия · читаемость выборки
L2 lookahead       что известно на баре i? общая переменная в отборе и исходе?
L3 множественность реальный k · chance-band при этих размерах ячеек
L4 режим           не бычий ли это рынок? переносится ли mined→OOS
L5 механизм        обязан ли эффект быть верным? есть ли микроструктурное объяснение?
```
*Ворота:* ≥2 линзы подтверждают дефект → находка дальше не идёт.

**`5 · ACCOUNT`** — ledger, DSR внутри семьи, BH-FDR между семьями.
*Ворота:* порядок обязателен — **сначала кластерный CI, потом DSR** (DSR слеп к кластеризации).

**`6 · VERDICT`** — один из пяти, с названием решающего гейта, автозапись в ledger.

**`7 · FREEZE`** — выжившее замораживается со spec-hash и датой.
*Ворота:* отсечка берётся из файла — back-dating невозможен.

## V. COMBO LAB — здесь живёт множественность

Комбинаторика — самая опасная часть системы. 2026-08-09 она выдала 46 комбинаций,
48 правил выхода и 312,189 ячеек, и всё это оказалось шумом. Поэтому три вещи встроены
в API, а не добавлены после:

```python
lab = ComboLab(space=dict(head=TOKENS, mid=TOKENS, tail=["T6"]),   # ① размер объявлен
               mined="2021-05→2023-12", oos="2024-01→2026-07",     # ② OOS ДО поиска
               metric="median_ret_pct", min_n=100)
lab.run()           # ранжирует ТОЛЬКО на mined
lab.chance_band()   # ③ разброс случайных ячеек тех же размеров — печатается всегда
lab.freeze_top(3)   # финалисты уходят в forward-реестр, НЕ в книгу
```

**Combo Lab не имеет права выдать вердикт.** Его выход — кандидаты для `FREEZE`.
Основание: лучшая из 46 ячеек лежала внутри полосы случайности, ранг mined↔OOS = −0.03.

## VI. Агенты, скилы, человек

| роль | кто | почему |
|---|---|---|
| контракт, измерение, вердикт | **код** | должен **отказывать**, а не соглашаться |
| процедура исследования | **скил** `quant-study` | план-first, порядок гейтов, формат вердикта |
| **DESTROY — 5 линз** | **агенты, параллельно** | единственное место, где мульти-агентность совпадает с нашими режимами отказа |
| слепой дизайн спецификации | **агент без памяти** | слой A загрязнения снимается только отдельной сессией |
| широкие сканы | **агенты** | когда ответ — список, а не утверждение |
| генерация гипотез | **человек** | агент множит `k` и не считает его |
| «обязан ли механизм быть верным» | **человек** | этот вопрос к одному графику нашёл то, что пропустили 5 слоёв |

**Различие:** агент допускается туда, где его задача — **разрушать**, и не допускается туда,
где он **порождает**.

## VIII. Поверхности

```
CLI    python studio.py study <spec.yaml> · combo · forward · ledger · sources
API    /api/studio/{study,combo,forward,ledger,sources}      (read-only отчёты)
UI     вкладка 🔬 Analytic Studio:
         ├ Sources    — что подключено, контракт, свежесть
         ├ Study      — спецификация → вердикт с решающим гейтом
         ├ Combo Lab  — пространство, полоса случайности, mined→OOS
         ├ Forward    — реестр + «дней до читаемости»
         └ Ledger     — k по семьям, DSR, FDR
```

UI **не считает** — показывает результат CLI/API. Одна вычислительная тропа: два пути
с разными контрактами — это в точности причина бага 2026-08-09.
