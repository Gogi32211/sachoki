მიზანი
------
რატომ ხდება, რომ ცოცხალ TradingView chart-ზე წაკითხული სიგნალების კოდები ზოგჯერ
არ ემთხვევა Studio DB-ს (და ამიტომ Sequence Builder / Ultra screener აბრუნებს
"0 match"-ს ან განსხვავებულ label-ებს). პლუს ყველა ფილტრის აუდიტი — რომელი
სიგნალია რისკის ქვეშ, და ფიქსი, რაც ავაშენეთ (DB-ზე დაფუძნებული chart).


================================================================================
1. მთავარი დასკვნა
================================================================================
TradingView და Studio DB სხვადასხვა ფასის feed-ზე დგანან:
  - TradingView chart  = TradingView-ის კონსოლიდირებული ფასის feed + ცოცხალი Pine
  - Studio DB          = Massive API feed + Python-port enrichment (და შეიძლება
                         stale იყოს: მაგ. JOBY მხოლოდ 2026-05-27-მდე ტესტის დროს)

მოცულობა (volume) იდენტურია ორ feed-ში. ფასები (OHLC) კი ოდნავ განსხვავდება.
=> ნებისმიერი სიგნალი, რომელიც მგრძნობიარეა ზუსტ ფასზე (განსაკუთრებით cumulative
   ინდიკატორები და ცენტების დონეზე wick-შედარებები), შეიძლება სხვანაირად იკითხოს
   chart-ზე, ვიდრე DB-ში.
=> მხოლოდ-მოცულობითი სიგნალები უსაფრთხოა (ემთხვევა).

ეს არც კოდის bug-ია და არც matcher-ის bug-ი — ეს მონაცემთა-წყაროს სხვაობაა.

4. სრული FILTER DIVERGENCE AUDIT (Ultra Scan / Advanced Filters)
================================================================================
წესი: რისკი = ზუსტ ფასზე მგრძნობელობა.
  Cumulative ინდიკატორები (EMA/RSI/CCI/ATR/PSAR/Bollinger/WVF/Fourier) = HIGH
  ცენტების დონეზე გეომეტრია (wick/penetration/body/gap/exact-cross/doji) = HIGH
  უხეში სანთლის მიმართულება / engulfing                                  = MEDIUM
  სუფთა მოცულობა                                                          = LOW (უსაფრთხო)

5. ფიქსი, რაც ავაშენეთ — DB-ზე დაფუძნებული chart Studio-ში
================================================================================
ახალი Studio tab: "DB Chart" (Exact Sequence-ის გვერდით). Component DbCandleChart.jsx.
  - Backend: /api/studio/bars/{ticker} გაფართოვდა — აბრუნებს ყველა 6 ხაზს
    (t_sig/z_sig, l_sig, composite_full_suffix, bar_body_wick, bar_gap_range,
     bar_line5) + swing_type_3 + pivot-ები, პირდაპირ DB-დან.
  - Frontend: lightweight-charts სანთლები + მოცულობა (bucket ფერები) + T/Z მარკერები;
    გადაატარე მაუსი ნებისმიერ ბარზე -> tooltip აჩვენებს ზუსტ 6 DB ხაზს.
  - ეს არის ზუსტი კოდები, რასაც Sequence Builder / Ultra screener იყენებს, ანუ რასაც
    აქ წაიკითხავ, დაემთხვევა (TradingView feed-ის სხვაობის გარეშე).

როგორ გამოვიყენო: Studio -> DB Chart -> ჩაწერე ticker -> Load -> გადაატარე ბარებზე.
Sequence Builder-ისთვის კოდები აქედან აიღე, არა TradingView-დან.

6. პრაქტიკული წესები
================================================================================
  1. ენდე ნებისმიერ chart-ზე (TV ან DB): L-კოდები, vol bucket, V x N, VA (მოცულობა).
  2. გადაამოწმე DB Chart-ზე, სანამ მოქმედებ: ყველაფერი TIER 1-ში

  3. TIER 2 ჩვეულებრივ ემთხვევა; borderline-ზე გადაამოწმე. უყურე LL<->HL / HH<->LH.
  4. Sequence Builder: კოდები DB Chart-იდან აიღე, ზუსტად დაწერე (ტირეებითურთ, მაგ.
