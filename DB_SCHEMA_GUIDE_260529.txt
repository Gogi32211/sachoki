WHAT THIS IS
------------
A single DuckDB analytics database of US daily stock bars (OHLCV) that has been
"enriched" — every bar carries ~350 precomputed signal / pattern / forward-return
columns. It powers the Sachoki screener (Ultra Scan, Sequence Builder, Studio,
DB Chart). It is NOT a live feed; it is a precomputed analytics store rebuilt by
bulk CSV import and topped up daily by an incremental "delta append".

  File   : /Users/sachoki/Downloads/studio_analytics.duckdb
  Engine : DuckDB (columnar, single file)
  Size   : ~2.4 GB
  Source : Massive API OHLCV → Python signal engines (ports of TradingView Pine
           scripts) → DuckDB. NOTE: prices differ slightly from a TradingView
           chart feed (volume is identical); see CHART_VS_DB_DIVERGENCE doc.

  universes:
     universe    rows        tickers   max date
     sp500         743,072       610    2026-05-28
     nasdaq      3,059,205     3,302    2026-05-28
     russell2k   4,419,564     5,001    2026-05-27 (being topped up to 05-28)

  Tickers can appear in more than one universe; treat (ticker, universe, date) as
  the unique key. Filter by `universe` for clean per-index analysis.

ALL VALUES ARE PRECOMPUTED PER BAR with NO lookahead in the signals themselves
(a signal at bar i uses only data up to bar i). The forward-return columns (fwd_*,
mfe_*, mae_*) DO look ahead by design — they are the OUTCOME labels for backtesting
and must never be used as model inputs.

================================================================================
HOW THE DATA IS MAINTAINED
================================================================================
  • Bulk import: bulk_export CSVs (one per universe) → DuckDB `bars`, then enrichment
    computes all derived columns. Recorded in import_log.
  • Daily top-up: studio.incremental_delta appends the latest bar(s) per ticker
    (DELETE-then-INSERT on (universe,ticker,date) for idempotency) and re-runs the
    enricher so rolling columns (RSI/ATR/avg_vol/pivots/suffixes/Pine engines) stay
    correct. Forward-return labels for newly-resolved tail bars are backfilled by
    studio.backfill_fwd (purely additive — only previously-NULL labels get filled).
  • All signal columns are Python ports of TradingView Pine scripts (260308, 260321,
    260403_Delta, 260418_F, 260523_WYC/PREBREAK/TZ_WLNBB, etc.).


================================================================================
QUICK USAGE NOTES FOR ANOTHER CHAT
================================================================================
  • Connect read-only:  duckdb.connect('/Users/sachoki/Downloads/studio_analytics.duckdb', read_only=True)
  • Boolean signal columns are 1/0 (or true/false). String columns ('' = none).
  • To study a signal's edge:   filter rows where the flag = 1, then aggregate
    fwd_5d / mfe_20d / hit_* against an unfiltered baseline. Compare LIFT vs baseline.
  • For reversal/structure work use swing_type_3 (+ fwd_swing_ret_3), NOT fixed-day
    returns — swings are not day-bounded.
  • VOLUME-based signals (L*, vol_bucket, V×N) match any chart. PRICE-sensitive ones
    (suffix, bar_line5, RSI/CCI/PSAR/EMA, WYC, prebreak) can differ from TradingView
    because the price feed differs — trust the DB's own values for DB queries.
  • Don't leak: fwd_*/mfe_*/mae_*/hit_*/drop_* are OUTCOMES, never inputs.
