CHART (TradingView) vs DB (Studio/Massive) — FULL DIVERGENCE ANALYSIS
2026-05-29 · Sachoki Screener · DuckDB studio_analytics (8.22M bars, 5y)

PURPOSE
-------
Why signal codes read off the live TradingView chart sometimes do NOT match the
Studio DB (and so the Sequence Builder / Ultra screener return "0 matches" or
different labels). Plus a full per-filter audit of which signals are at risk, and
the fix we built (a DB-sourced chart).


================================================================================
1. THE CORE FINDING
================================================================================
TradingView and the Studio DB run on DIFFERENT price feeds:
  - TradingView chart   = TradingView's consolidated price feed + live Pine indicator
  - Studio DB           = Massive API feed + Python-ported enrichment (and can be
                          stale: e.g. JOBY only to 2026-05-27 at time of test)

VOLUME is identical across the two feeds. OHLC PRICES differ by small amounts.
=> Any signal sensitive to exact price (especially cumulative indicators and
   penny-level wick comparisons) can read DIFFERENTLY on the chart vs the DB.
=> Volume-only signals are SAFE (match).

This is NOT a code bug and NOT a matcher bug — it is a data-source difference.

================================================================================
3. WHY THE SEQUENCE BUILDER RETURNED "0 MATCHES"
================================================================================
Three independent causes, all real (none a code bug):

(a) FEED DIVERGENCE — codes read off the TradingView chart don't exist on those
    exact DB bars (section 2). Fix: read codes from the DB Chart, not TradingView.

(b) OVER-SPECIFICATION — requiring many exact attributes across multiple
    consecutive bars collapses to 0. Example tested:
      bar-2 (Z1G + ED + PB-R2L)  AND  bar-1 (T3 + NURI + PS-R2X) consecutive
        - each bar's full signature alone: 6,863 and 2,858 occurrences
        - the exact consecutive transition (all 6): 0 in 8.2M bars
      Sub-combos exist (Z1G/ED->T3/NURI = 227, etc.) but all-6 together = 0.

(c) TYPO / DASH — "PSR2X" vs "PS-R2X" (missing hyphen) => 0.
    Verified: as typed = 0 matches; corrected to PS-R2X = 1 match (the JOBY bars).
    Lesson: exact spelling incl. hyphens matters. (Optional fix: make the builder
    dash-insensitive — not yet applied.)

4. FULL FILTER DIVERGENCE AUDIT (Ultra Scan / Advanced Filters)
================================================================================
RULE: risk = sensitivity to small price differences.
  Cumulative indicators (EMA/RSI/CCI/ATR/PSAR/Bollinger/WVF/Fourier) = HIGH
  Penny-level geometry (wick/penetration/body/gap/exact-cross/doji)   = HIGH
  Gross candle direction / engulfing                                  = MEDIUM
  Pure volume                                                         = LOW (safe)

  suffix:   NE / E / WK up/dn/both                            (wick vs prev hi/lo)

================================================================================
5. THE FIX WE BUILT — DB-sourced chart in Studio
================================================================================
New Studio tab: "DB Chart" (next to Exact Sequence). Component DbCandleChart.jsx.
  - Backend: /api/studio/bars/{ticker} extended to return all 6 lines
    (t_sig/z_sig, l_sig, composite_full_suffix, bar_body_wick, bar_gap_range,
     bar_line5) + swing_type_3 + pivots, straight from the DB.
  - Frontend: lightweight-charts candles + volume (bucket colours) + T/Z markers;
    HOVER any bar -> tooltip shows the exact 6 DB lines.
  - These are the EXACT codes the Sequence Builder / Ultra screener use, so what you
    read here will match (no TradingView feed mismatch).

HOW TO USE: Studio -> DB Chart -> type ticker -> Load -> hover bars to read 6 lines.
Take codes for the Sequence Builder FROM THIS CHART, not from TradingView.


================================================================================
6. PRACTICAL RULES
================================================================================
  1. Trust on any chart (TV or DB): L-codes, vol buckets, V x N, VA  (volume-based).
  2. Cross-check on the DB Chart before acting: everything in TIER 1
     (line5, suffix, RSI/CCI/PSAR/EMA/WVF, PREUP/PREDN, WYC, PREBREAK, RS, Macro).
  3. TIER 2 usually agrees; verify on borderline candles. Watch LL<->HL / HH<->LH.
  4. For the Sequence Builder: read codes from the DB Chart, spell exactly
     (including hyphens, e.g. PS-R2X not PSR2X), and don't over-specify (1-2 lines
     across a sequence, not all 6 on every bar, or you get 0).
  5. Ultra screener and DB Chart both read the same DuckDB -> they always agree
     with each other; only TradingView differs.
